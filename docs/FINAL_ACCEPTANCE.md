# Этап 6: интерфейс и финальная приёмка

Приложение — демонстрационный MVP, не универсальная экспертиза документов.
UI отправляет файл в настоящий FastAPI; правила и редактирование выполняются
только в backend. Синтетические примеры создают настоящий DOCX и проходят тот же
API. В пользовательском интерфейсе нет mock-провайдера или фиктивных замечаний.

## Запуск в Windows Git Bash

Команды выполняются из корня проекта при запущенном Docker Desktop:

```bash
cd '/c/workplace/AI_ Inspector_doc'
test -f .env || cp .env.example .env
docker version
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl --fail http://localhost:18000/health
curl --fail http://localhost:18000/documents/options
curl --fail http://localhost:8501/_stcore/health
curl --fail http://localhost:5000/health
docker compose exec api python -m pytest -v
docker compose exec api python -m pytest --cov=backend --cov-report=term-missing
```

Ожидается образ `document-ai-inspector:stage6`, сервисы api/ui/mlflow healthy,
health API `{"status":"ok"}`, options с реальным профилем `default` v1.0.0,
лимитом загрузки и временем обработки. Обычный pytest не вызывает реальные LLM
и исключает external. Обязательный процент покрытия пока не установлен.

Адреса для браузера:

| Назначение | Адрес |
|---|---|
| Streamlit | http://localhost:8501 |
| API / OpenAPI | http://localhost:18000/docs |
| MLflow | http://localhost:5000 |

В сети Compose UI использует `http://api:8000`, API использует
`http://mlflow:5000`; Windows Ollama доступна как
`http://host.docker.internal:11434/v1`. Порт 18000 на хосте уже использовался
в предыдущем этапе и сохранён. Команды с localhost:8000 к этому Compose не относятся.

## Проверка интерфейса

1. Откройте Streamlit. По умолчанию выбран «Без LLM», автоисправление и PDF
   выключены. Открытие страницы или изменение выбора не отправляет файл.
2. Выберите «Синтетический пример» → «Ошибки оформления» и `default`.
   При необходимости сохраните пример кнопкой «Скачать пример DOCX».
3. Включите разрешённые правки и PDF, нажмите «Проверить документ».
   Ожидается четыре замечания: одно исправлено (10 → 14 pt), три требуют
   ручной проверки. Разрешена именно правка размера шрифта, а не всех свойств.
4. Проверьте источник `rule`, XPath/место, цитату, actual/expected,
   рекомендации, статус и журнал. Должно быть явно указано прохождение инвариантов.
5. Скачайте исправленный DOCX, исходник, JSON и PDF. Откройте DOCX/PDF,
   сравните текст и таблицу, осмотрите вёрстку. JSON должен содержать UUID
   задания, профиль, SHA-256 оригинала и те же замечания.
6. Проверьте SHA-256 скачанного исходника и скачанного до проверки примера
   (подставьте реальные пути загрузок браузера):

   ```bash
   sha256sum '/c/Users/ВАШЕ_ИМЯ/Downloads/format_errors.docx' '/c/Users/ВАШЕ_ИМЯ/Downloads/UUID-original.docx'
   ```

   Ожидается одинаковая контрольная сумма. Исправленная копия имеет другую сумму.
7. Переключите источник на «Загрузить DOCX» и загрузите сохранённый пример.
   Повторите проверку. Новый документ/параметры должны убрать старый результат;
   нажатие кнопки скачивания не должно повторять проверку.
8. Проверьте «Без ошибок оформления»: без LLM ожидается пустая таблица.
   Повреждённый DOCX должен дать понятный отказ без выдачи старых результатов.

PDF отображается статусом/числом страниц и скачивается для просмотра в браузере
или PDF-приложении. Встраивание PDF через небезопасный HTML не используется.
При отсутствии LibreOffice/таймауте UI показывает причину; DOCX и JSON остаются
доступны. При провале инвариантов исправленный DOCX не предлагается, исходник
и JSON доступны. Успешный PDF и сходное число страниц не доказывают отсутствие
всех дефектов вёрстки.

В репозитории сейчас один реальный профиль. UI получает его и версию через
`GET /documents/options`; дополнительные фиктивные «шаблоны» не показываются.

## Локальная смысловая проверка

Установите нужную локальную модель Ollama на Windows. Укажите её фактическое
имя в `.env`, например значение из собственного `ollama list`, и адрес:

```text
OLLAMA_BASE_URL=http://host.docker.internal:11434/v1
OLLAMA_MODEL=<точное имя установленной локальной модели>
```

Не используйте cloud-алиасы Ollama. После изменения `.env`:

```bash
docker compose up -d --build
```

В UI выберите «Смысловое противоречие», провайдер Ollama и нажмите проверку.
Модель получает два раздела со сроками 10 и 30 дней. Ожидается реальный результат,
а не гарантированное одно замечание: LLM может пропустить ошибку или вернуть
невалидную цитату. UI показывает статус, источник `llm` и принятые цитаты;
смысловые факты не исправляются автоматически. Если LLM недоступна, формальная
проверка, JSON и DOCX должны сохраниться. Пустой успешный ответ LLM не доказывает
отсутствие смысловых ошибок.

Yandex — только синтетические документы, выбранный провайдер и **два** явных
подтверждения в UI: синтетические данные и разрешение платного вызова. Они
привязаны к выбранному файлу. Без обоих кнопка заблокирована, клиент и backend
также проверяют разрешение. Ключи и каталог задаются только в `.env` по корневому
README; они не вводятся и не отображаются в UI. Самостоятельно запускайте облако
только если согласны на расходы. Никакая команда обычного pytest не вызывает его.

vLLM требует уже существующего сервера и настроенных VLLM_BASE_URL/VLLM_MODEL;
GPU-развёртывание и реальная GPU-проверка не выполнялись.

## MLflow и воспроизводимая оценка

Обычная проверка DOCX не обращается к MLflow. Benchmark запускается отдельно:

```bash
docker compose exec api python -m evaluation.benchmark --dry-run
```

Ожидается явно помеченный mock-run, отдельный эксперимент
`semantic-benchmark-mock`, 24 кейса, TP=0, FP=0, FN=12. Это проверка plumbing,
не оценка реальной модели. Опциональная реальная локальная оценка:

```bash
docker compose exec api python -m evaluation.benchmark --provider ollama
```

Реальные метрики не предопределены. Проверяйте версии prompt/dataset/matching,
валидацию цитат и отрицательные кейсы вместе с F1. Разбор сохранённого Ollama
и правила matcher v2: [отчёт этапа 5](../evaluation/reports/ollama-stage5-analysis.md).
Prompt v1 и ground truth не изменены; отдельное предложение prompt v2 не включено.
Маленький синтетический набор не доказывает качество на реальных документах.

## Диагностика

Если страница не открывается или не видит API:

```bash
docker version
docker context show
docker compose config --quiet
docker compose ps -a
docker compose logs --tail=100 api ui mlflow
curl --fail http://localhost:18000/health
docker compose exec ui python -c 'import urllib.request; print(urllib.request.urlopen("http://api:8000/health",timeout=5).read().decode())'
docker compose exec api libreoffice --version
```

- `docker version` без Server: дождитесь Docker Engine, проверьте контекст.
- Старый placeholder или отсутствие `/documents/options`: пересоберите и
  пересоздайте сервисы командой `docker compose up -d --build`; проверьте тег stage6.
- Занятый порт: освободите соответствующий 18000/8501/5000; не меняйте только
  URL в браузере без согласования port mapping и API_BASE_URL.
- Ошибка PDF: проверьте LibreOffice, `RENDER_TIMEOUT_SECONDS` и общий
  `PROCESSING_TIMEOUT_SECONDS`. Они ограничивают реальную обработку.
- UI timeout: API мог продолжить задание. Автоповтора POST нет; повторное нажатие
  создаёт новое задание и при выбранной LLM может снова вызвать модель.
- API_REQUEST_TIMEOUT_SECONDS у UI равен 630: больше максимального backend timeout
  600 секунд. GET профилей и скачивания имеют отдельный timeout 10 секунд.
- `Permission denied` MLflow/SQLite: проверьте логи и права volume; не удаляйте
  данные для устранения ошибки подключения. UID/GID контейнера — 10001.

Просмотр логов и остановка:

```bash
docker compose logs -f api
# Ctrl+C прекращает просмотр логов
docker compose down
```

`down` сохраняет documents_data и mlflow_data. Не используйте `down -v`, если
нужно сохранить документы и эксперименты. Пользовательские файлы/результаты не
включены в Docker build context; Dockerfile копирует только разрешённые каталоги.
`.env` исключён из сборки и Git. Не публикуйте полный `docker compose config`.

## Демо на 5 минут

| Время | Действие и смысл |
|---|---|
| 0:00–0:30 | Показать healthy сервисы, UI и профиль; LLM по умолчанию выключена |
| 0:30–1:45 | Синтетический DOCX с четырьмя ошибками, безопасная правка и таблица |
| 1:45–2:45 | Скачать исходник/копию/JSON/PDF, показать 10 → 14 pt и сохранённый текст |
| 2:45–4:00 | При заранее готовой Ollama проверить 10 против 30 дней; показать цитаты либо честный статус отказа |
| 4:00–5:00 | Показать сохранённый реальный run MLflow, F1 вместе с validation errors и ограничениями |

Подготовьте модели и образ заранее. Не начинайте длительную сборку или полный
benchmark во время демо. Без Ollama покажите автономную проверку и сохранённый
run как исторический результат, не выдавая его за текущий ответ модели.

# Анализ ошибок Ollama, этап 5

Источник: сохранённый запуск
[`real-7d083fee55ad4e90ae91595cfb0a91fc`](../../results/benchmarks/real-7d083fee55ad4e90ae91595cfb0a91fc/summary.json),
Ollama `qwen2.5:7b-instruct`, temperature=0, max_tokens=1024,
timeout=120 секунд, retries=0. 24 синтетических кейса: 12 положительных,
8 отрицательных и 4 неоднозначных. Ground truth, prompt v1 и сохранённый run
не изменены. Реальные модели и MLflow Server при анализе не вызывались.

Найдены две проблемы реализации оценки: чувствительность matcher к конечной
точке и недостаточная диагностика отклонённых ответов. Три принятых ложных
противоречия относятся к поведению модели, а не к дефекту разметки.

## 1. Пять `invalid_llm_evidence`

| Кейс | Результат baseline | Влияние на event-level оценку |
|---|---|---|
| positive-retention | failed, JSON valid, references invalid | FN=1 |
| positive-warranty | failed, JSON valid, references invalid | FN=1 |
| positive-staff | failed, JSON valid, references invalid | FN=1 |
| negative-same | failed, JSON valid, references invalid | TP=FP=FN=0 |
| negative-history | failed, JSON valid, references invalid | TP=FP=FN=0 |

По коду `grounded_findings` этот код ошибки имеет две причины:

1. Цитата после удаления внешних пробелов короче 8 символов либо не содержит
   букв/цифр. Короткие исходные строки уже блокирует Pydantic, но строка из
   пробелов или знаков достаточной длины может дойти до grounding.
2. Цитата не является точной непрерывной подстрокой указанного исходного фрагмента.
   Даже визуально похожие символы, изменённые пробелы или перефразирование не принимаются.

**Невозможно установить, какая конкретно цитата и какой символ были неверны в
каждом из пяти случаев.** В cases.json сохранены только общий error_code и пустой
prediction_evidence; отсутствуют исходные ответы, пояснения и координаты отказа.
Пустой prediction_evidence здесь означает отсутствие *принятых* замечаний,
а не пустой ответ модели. При issues=[] этот код вообще не возникает.
Поэтому во всех пяти ответах было хотя бы одно issue, но точное число неизвестно.
Перефразирование, оформление чисел или пробелы — возможные причины, не доказанные
факты конкретного запуска. Повторный запрос модели не восстановил бы старый ответ.

Исправлена наблюдаемость будущих запусков: сохраняются число issues, число
отброшенных issues и причина первой ошибки с индексами issue/reference.
Отклонённые тексты, произвольные ID и объяснения в диагностику не копируются.
Политика отказа всего ответа и строгое сравнение с источником сохранены.

## 2. `positive-storage`: одновременно FP=1 и FN=1

ID пары совпадают: `word/document.xml:/w:document/w:body/w:p[2]` и `w:p[4]`.
Обе принятые цитаты дословны и содержат несовместимые единственные места хранения.
Единственное отличие от эталонных строк — отсутствие конечной точки:

| Источник | Окончание эталона | Окончание цитаты модели |
|---|---|---|
| Первый фрагмент | `площадка Север.` | `площадка Север` |
| Второй фрагмент | `площадка Юг.` | `площадка Юг` |

Grounding правильно принял эти подстроки. Но matcher v1 проверял
`gold.quote in prediction.quote`, поэтому строки с точками не помещались
в цитаты без точек. Несопоставленное предсказание дало FP=1, несопоставленный
эталон — FN=1. Это один дефект сопоставления, а не две ошибки LLM.

Matcher v2 игнорирует внешние пробелы и одну конечную точку, сохраняя полный
остальной текст, значения, условия и отрицания. Ground truth не менялся.
Отдельная версия нужна, чтобы не смешивать старые и новые результаты оценки.

| Оценка тех же сохранённых ответов | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| Исходный matcher v1 | 8 | 4 | 4 | 0,6667 | 0,6667 | 0,6667 |
| Офлайн-пересчёт matcher v2 | 9 | 3 | 3 | 0,75 | 0,75 | 0,75 |

Изменился только positive-storage. Это постфактум исправление измерения,
а не новое измерение или улучшение модели. В старый MLflow run ничего не записывалось.

## 3. Три ложных противоречия на отрицательных кейсах

| Кейс | Смысл исходных утверждений | Почему противоречия нет |
|---|---|---|
| negative-phases | 8 сотрудников на пилотном этапе, 12 на промышленном | Значения относятся к разным этапам; штат может изменяться |
| negative-units | 1000000 рублей и один миллион рублей | Одинаковая величина в цифровой и словесной записи |
| negative-subset | Согласование для каждой закупки А; согласование для закупок А свыше 100 тысяч | Общее правило влечёт частное; освобождение остальных закупок не утверждается |

Во всех трёх случаях ссылки и цитаты корректны. Валидатор доказывает наличие
цитат в документе, но не логическую несовместимость утверждений. Поэтому он
правильно пропускает их к оценке, а ground truth правильно даёт FP.
В сохранённых артефактах отсутствуют explanation, так что внутренний ход
решения модели установить нельзя. Наблюдаемая ошибка — неверная классификация
совместимых утверждений; она согласуется с игнорированием контекста этапов,
ошибочной трактовкой эквивалентных числовых представлений и частного правила.

Предложения для отдельного [prompt v2](../prompts/contradictions-v2-proposal.md):
явное сравнение контекста, эквивалентности величин, логики общего/частного правила,
дословное копирование цитат и пустой список при отсутствии уверенной ошибки.
Рабочий prompt v1 не изменён. Необходима также проверка на новом размеченном
наборе, чтобы не принять подстройку под просмотренные случаи за улучшение качества.

## 4. Отсутствие замечаний

`{"issues":[]}` проходит SemanticResponse, цикл проверки ссылок не выполняется,
возвращается findings=[], status=completed, JSON-valid=true и references-valid=true.
Это допустимый ответ «не нашёл», а не доказательство корректности документа.
Для положительного документа он даёт FN; для отрицательного — ни TP, ни FP, ни FN.

`{}`, `{"issues":null}`, сломанная схема или непустой issue без корректных ссылок
не эквивалентны пустому списку и отклоняются. Все принятые замечания при одной
ошибке grounding отбрасываются; это существующая политика, не новая эвристика.

В исследованном run три успешных пустых результата: negative-objects,
negative-conditions и negative-unrelated. negative-same и negative-history
являются сбоями валидации и не должны описываться как успешные пустые результаты.

## 5. Что скрывалось за агрегатами

JSON-valid=24/24=100% отражает только схему, а не корректность цитат или смысла.
References-valid=19/24=79,17% включает три пустых ответа, в которых ссылок не было.
У непустых ответов по логике валидатора успешно проверены 16 из 21 кейса
(76,19%); число отдельных issues в пяти сбойных ответах неизвестно.

API errors=0 совместимо с пятью ошибками валидации: запросы успешно вернули ответ,
но ответы не прошли grounding. Ошибок с JSON-схемой и кодом invalid_llm_reference
в сохранённом run нет. Глобальный failed_case_count=5 уже показывал проблему,
однако не разделял её причины и категории документов.

Event-level F1 оценивает **принятые** замечания. Три сбоя положительных кейсов
уже ухудшают recall через FN. Два сбоя отрицательных кейсов не добавляют FP:
значения TP=FP=FN=0 у них неотличимы от успешного отсутствия замечаний, если
не читать status. Следовательно, один F1 может скрыть систематическую генерацию
невалидных противоречий на отрицательных документах.

Не следует произвольно превращать каждый отказ в FP: точное число и содержание
отклонённых событий неизвестны. Вместо изменения этой политики добавлены
validation/evidence/reference/JSON error counts, разбиение validation errors по
positive/negative/ambiguous, failed_negative_case_count и successful_empty_case_count.
Для этого run: validation=5, evidence=5, positive validation=3,
negative validation=2, успешных пустых=3, отрицательных кейсов с принятым FP=3 из 8.

У новых запусков есть наблюдаемые счётчики непустых и отброшенных issues с отдельным
покрытием. Для старого run покрытие новых полей равно нулю: неизвестное не
превращается в утверждение «отброшено ноль». Четыре неоднозначных кейса имеют
по одному замечанию и исключены из качества в обеих версиях оценки.

## Проверка и воспроизведение

Добавлены регрессионные проверки terminal-period matching, сохранения условий
и чисел, пяти причин отказа grounding, пустых/сломанных ответов, полного отказа
при смешанном валидном/невалидном ответе, различия failed-negative/empty и офлайн
пересчёта замороженной синтетической копии baseline из tests/fixtures.
Воспроизведены все принятые цитаты и исходные TP/FP/FN, совпадение датасета с
manifest и его hash. Исторические отклонённые цитаты не проверялись: их нет.

После окончательных изменений локально выполнены перечисленные ниже восемь
тестовых модулей: **81 passed**, одно предупреждение Starlette/AnyIO о deprecated
alias. `git diff --check` прошёл. summary/cases/manifest исходного запуска
побайтово совпадают с замороженной копией, сделанной до исправлений.
Hash рабочего файла prompts.py совпадает с версией HEAD.


перезаписывается. Никаких аргументов для вызова модели у этой команды нет.

настоящая проверка Docker/Linux в рамках этого разбора не выполнялась.

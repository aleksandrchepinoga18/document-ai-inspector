# Команды для Codex — по очереди, НЕ все сразу

## Как пользоваться

1. Создай в VS Code пустую папку `document-ai-inspector`.
2. Скопируй туда **исправленное** ТЗ `TECHNICAL_SPEC_REVISED.md` и переименуй в `TECHNICAL_SPEC.md`.
3. Открой эту папку в VS Code и открой Codex **в режиме работы с папкой проекта**.
4. Отправь **только команду №1** из этого файла. Когда Codex завершит, открой Git Bash в корне проекта и **сам** выполни проверку.
5. Пришли логи/ошибки Codex на исправление; только после успешной проверки переходи к №2. Точно так же до №6.
6. Важно: команды ниже — **сообщения Codex**, блоки `bash` — **вводить самому в Git Bash**, не в чат Codex.

В контейнере API должны присутствовать исходники, тесты и pytest/pytest-cov. Добавь MLflow с сохраняемыми данными, LibreOffice подготовь в образе обработки документов. Подключение Ollama из контейнера предусмотри через `host.docker.internal`, но LLM пока не реализуй. Убедись, что `/health` возвращает `{"status":"ok"}`. Не подключай внешние платные API. Составь README с ручными командами для Windows Git Bash. Не переходи к следующим этапам, не добавляй ненужные технологии. В финале дай список файлов, выполненные проверки, команды для моего самостоятельного запуска и ожидаемые результаты. Если чего-то не проверял, так и напиши.

**В Git Bash (из корня проекта):**


**Приёмка:** три сервиса поднимаются, `/health` возвращает `status: ok`, тесты проходят, интерфейсы доступны.
